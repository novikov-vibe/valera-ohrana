# SSRF (подделка запросов со стороны сервера)

## Суть
Сервер делает исходящий HTTP-запрос по адресу, на который влияет пользователь.
Запрос уходит из доверенной сети и с правами сервера, поэтому злоумышленник
дотягивается до того, что снаружи закрыто: loopback-админки, внутренние сервисы,
метаданные облака (временные ключи), соседние БД и очереди с HTTP-интерфейсом.
«Слепой» SSRF (ответ не возвращается) всё равно опасен: им сканируют сеть и
дёргают изменяющие эндпоинты внутренних систем.

## Где появляется в коде
- Загрузка по ссылке: «импортировать аудио/картинку/документ по URL», превью
  ссылок (unfurl), аватар по URL, RSS/iCal-подписки.
- Вебхуки: пользователь или админ задаёт URL, сервер потом шлёт туда события.
- Интеграции с настраиваемым базовым адресом (`YOUTRACK_URL`, `MATTERMOST_URL`
  из формы админки, а не из env) — особенно если базовый URL склеивается с путём
  от пользователя.
- Частичные URL: пользователь передаёт «id файла» или путь, а сервер подставляет
  его в `f"{BASE}/{user_path}"` — `../`, `@`, `#` меняют смысл.
- Парсеры форматов, которые сами ходят в сеть: XML с внешними сущностями, SVG,
  офисные документы, PDF-рендереры, ffmpeg с сетевыми протоколами.
- Инструменты LLM вида `fetch_url(url)` — модель становится источником URL.
- Заголовки, которые читает аналитика (Referer), обработчики OAuth/OIDC
  `jwks_uri`/discovery из недоверенного источника.

Плохо:
```python
@router.post("/import")
async def import_audio(url: str, user=Depends(auth.current_user)):
    async with httpx.AsyncClient(follow_redirects=True) as c:   # без таймаута
        r = await c.get(url)                                     # любой хост/схема/порт
```
Хорошо:
```python
ALLOWED = {"drive.google.com", "docs.google.com"}               # из config.yaml
u = httpx.URL(url)
if u.scheme != "https" or u.host not in ALLOWED or u.port not in (None, 443):
    raise HTTPException(400)
ip = await resolve_public_only(u.host)        # все A/AAAA — публичные, иначе 400
async with httpx.AsyncClient(follow_redirects=False, timeout=10,
                             transport=PinnedTransport(u.host, ip)) as c:
    r = await c.get(u)                        # редирект — заново через ту же проверку
```

## Как искать
```
rg -n "httpx\.(get|post|AsyncClient|Client)|requests\.(get|post|request)|urlopen|aiohttp\.ClientSession" app/
rg -n "follow_redirects\s*=\s*True|allow_redirects\s*=\s*True"
rg -n "webhook|callback_url|import.*url|fetch_url|unfurl|preview" -i
rg -n "f\"\{.*(base|BASE|url|URL)\}/\{" app/          # склейка базового URL с вводом
rg -n "lxml|xml\.etree|defusedxml|resolve_entities"    # XML с сетью
rg -n "ffmpeg.*(-i|input)" app/                        # ffmpeg принимает URL как вход
```
Вопросы ревьюера:
- Откуда берётся хост? Env/конфиг — ок; БД, форма, сообщение чата, вывод LLM — нет.
- Проверка хоста и сам запрос используют один и тот же разобранный объект URL?
- Следует ли клиент редиректам? Проверяется ли каждый шаг редиректа?
- Резолвится ли имя один раз и подключение идёт именно к проверенному IP?
- Какие схемы разрешены (file:, gopher:, ftp: в urllib/curl)? Какие порты?
- Возвращается ли тело ответа/текст ошибки пользователю (утечка внутренних данных)?
- Есть ли таймаут и ограничение размера ответа?

## Обходы, о которых забывают
- **Чёрный список строк не ловит адрес.** Один и тот же IP записывается многими
  способами: десятичным числом, сокращённо, с ведущими нулями (восьмеричная
  трактовка), шестнадцатеричными октетами, через IPv6-обёртку IPv4. Сравнение
  строки `"127.0.0.1"` или `"localhost"` ничего не гарантирует — сравнивать нужно
  разобранный IP с диапазонами.
- **Имя, которое резолвится во внутренний адрес.** Домен злоумышленника может
  указывать на loopback или частную сеть; проверка «это не IP-литерал» бесполезна.
- **DNS rebinding.** Проверили имя — получили публичный IP; через секунду клиент
  резолвит снова и получает внутренний. Защита — пиннинг: подключаться к тому IP,
  который проверили, а не к имени.
- **Редиректы.** Разрешённый хост (или открытый редирект на нём) отвечает 30x
  во внутреннюю сеть, и клиент послушно идёт туда. `follow_redirects=True` +
  проверка только исходного URL = обход.
- **Расхождение парсеров URL.** Валидатор и HTTP-клиент по-разному понимают
  userinfo перед `@`, фрагмент `#`, обратный слэш, двойное кодирование, пробелы.
  Фильтр видит разрешённый хост, клиент идёт на другой. Проверка «начинается с /
  содержит разрешённый домен» (`startswith`, `in`, regex без якорей) ломается
  поддоменами и доменами-двойниками.
- **Белый список по суффиксу.** `host.endswith("corp.ru")` пропускает
  `evilcorp.ru`; нужен точный матч или `== d or endswith("." + d)`.
- **Ретраи и фолбэки.** Повторная попытка или запасной провайдер делают свой DNS-
  запрос мимо проверки.
- **Слепой SSRF «безопасен, ведь ответ не показываем»** — нет: побочные эффекты
  внутренних GET-эндпоинтов и сканирование портов по времени ответа.
- **IPv6.** Проверили только A-записи, а клиент подключился по AAAA.

## Как исправить правильно
1. Лучше не принимать URL вовсе: принимать идентификатор, а адрес собирать на
   сервере из базового URL в конфиге (схема, хост, порт, путь — фиксированы;
   пользовательское значение — только как экранированный сегмент/параметр).
2. Если нужен URL — белый список хостов с точным сравнением после разбора одним
   парсером; только `https`, только стандартный порт.
3. Если хост произвольный (вебхуки) — резолвить все A/AAAA, отклонять, если хоть
   один адрес не глобальный (`ipaddress.ip_address(x).is_global` плюс явный отказ
   для loopback, link-local, private, reserved, multicast, `169.254.169.254`);
   подключаться к проверенному IP (пиннинг), сохраняя имя для Host/SNI/сертификата.
4. Редиректы выключить; если нужны — обрабатывать вручную, прогоняя каждый
   `Location` через ту же проверку, с лимитом шагов.
5. Таймауты, лимит размера ответа, не возвращать пользователю сырое тело и тексты
   ошибок соединения.
6. Сеть: исходящий трафик воркера — через egress-прокси/файрвол только наружу;
   метаданные облака закрыть (IMDSv2 / hop limit). Это страховка, а не замена.
7. XML — `defusedxml`; ffmpeg — `-protocol_whitelist file` и локальный файл.

## Ложные срабатывания
- URL целиком из env/`config.yaml` (`YOUTRACK_URL`, `MATTERMOST_URL`), путь — из
  констант, пользовательские данные идут только в тело/JSON.
- Пользовательское значение подставлено как экранированный сегмент пути
  (`quote(id, safe="")`) или как query-параметр через `params=`.
- Запросы к фиксированным API провайдеров (ElevenLabs, DeepSeek, Google).
- Редирект-клиент, где адрес задаёт только админ через env при деплое.
