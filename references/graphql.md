# GraphQL

## Суть
GraphQL отдаёт клиенту единую точку входа и язык запросов: клиент сам решает, какие
поля, связи и сколько операций запросить. Уязвимости рождаются в реализации:
резолверы без проверки доступа (IDOR), раскрытая схема, отсутствие лимитов на
глубину и число операций, приём запросов в форматах, уязвимых к CSRF.

## Где появляется в коде
- Проверка доступа сделана в роуте `/graphql` (вошёл ли), а не в резолверах
  (можно ли этот объект и это поле).
- Резолвер `node(id:)`/`user(id:)`/`call(id:)` грузит запись по id без предиката видимости.
- Связи (`call { owner { email } }`, `team { members { ... } }`) отдают поля, которых
  нет в REST-ответе.
- Introspection и GraphiQL/Playground включены в проде; подсказки «Did you mean …».
- Нет лимитов на глубину, сложность, алиасы, батчинг, размер запроса.
- Эндпоинт принимает `GET` и `application/x-www-form-urlencoded`, мутации — без
  CSRF-защиты при cookie-сессии.
- Ошибки резолверов уходят клиенту со стеком.

```python
# плохо (Strawberry/Ariadne): доступ проверен только «вошёл ли»
@strawberry.type
class Query:
    @strawberry.field
    async def call(self, info, id: int) -> Call:
        return await db.fetchrow("SELECT * FROM calls WHERE id=$1", id)

# хорошо: та же функция доступа, что и в REST, внутри резолвера
    @strawberry.field
    async def call(self, info, id: int) -> Call | None:
        user = info.context.user
        return await load_call_for(user, id)   # предикат видимости в SQL, None если нельзя
```

```python
# лимиты и выключенная introspection (Strawberry)
schema = strawberry.Schema(query=Query, extensions=[
    QueryDepthLimiter(max_depth=8), MaxAliasesLimiter(max_alias_count=15),
    MaxTokensLimiter(max_token_count=2000), DisableIntrospection,
])
```

Node (Apollo Server 4): `introspection: false` в проде, `hideSchemaDetailsFromClientErrors`,
`graphql-depth-limit`, cost-analysis плагин, `csrfPrevention: true`, авторизация в
резолверах/директивах.

Вопросы ревьюера:
- Каждый резолвер, принимающий id, и каждая связь — где проверка доступа? Та же ли
  это функция, что в REST-части?
- Какие поля типа `User`/`Call` видит посторонний через вложенную связь?
- Включена ли introspection/IDE в проде? Отключены ли подсказки в ошибках?
- Есть ли лимиты глубины, алиасов, батчей, размера, сложности, таймаут?
- Как устроен лимит попыток для мутаций входа/кодов: считает ли он операции или
  HTTP-запросы?
- Какие методы и `Content-Type` принимает эндпоинт? Как защищены мутации от CSRF?

## Обходы, о которых забывают
- **Проверка на входе, а не в резолвере.** Вошедший пользователь через вложенные
  связи добирается до чужих объектов и полей, хотя «прямой» запрос защищён.
- **IDOR в аргументах.** Перебор id в `query { call(id: …) }` — тот же IDOR, только
  без отдельного URL; скрытые из списков объекты доступны по id.
- **Выключенная introspection ≠ скрытая схема.** Подсказки об опечатках в именах полей
  позволяют восстановить схему; клиентский JS тоже её содержит.
- **Наивный фильтр introspection.** Блокировка по строке/регулярке обходится
  пробелами, переносами, другим методом или кодировкой запроса. Отключать нужно
  в самом движке, а не фильтром по тексту.
- **Алиасы и батчи против лимитов.** Один HTTP-запрос может содержать сотни
  операций (через алиасы или массив запросов) — лимит, считающий HTTP-запросы, не
  замечает перебор кодов, купонов, паролей.
- **CSRF через GraphQL.** Если эндпоинт принимает `GET` или form-encoded `POST`,
  чужой сайт может отправить мутацию от имени вошедшего пользователя; «у нас JSON,
  значит CSRF не страшен» верно только при строгой проверке `Content-Type`.
- **DoS через глубину и цикличные связи.** `team → members → team → …` без лимита
  глубины и пагинации разгоняет нагрузку экспоненциально.
- **Мутации без проверки полей** — mass assignment (см. `api.md`): input-тип с полем
  `role` или `ownerId`.

## Как исправить правильно
- Авторизация в каждом резолвере запросов и мутаций, включая связи и `node`; общая
  функция доступа с REST; поле-уровневые права для чувствительных полей. Ненужные
  `node/nodes` — убрать.
- В проде: introspection и IDE выключены (или только для админов), подсказки в ошибках
  скрыты, стеков нет — подробности только в серверный лог.
- Лимиты: глубина, число алиасов, корневых полей, батч-операций, размер запроса,
  стоимость; пагинация по умолчанию; таймаут выполнения; DataLoader против N+1.
- Лимиты попыток для чувствительных мутаций считать по операциям/учётке, а не по
  HTTP-запросам; батчинг для них запретить.
- Принимать только `POST` с `Content-Type: application/json`; при cookie-сессии —
  CSRF-токен или проверка `Origin`.
- Input-типы — с точными скалярами и enum, без системных полей.

## Ложные срабатывания
- Публичный API с открытой схемой — задуманное поведение, если в схеме нет
  внутренних полей.
- Резолверы, получающие объект только из уже проверенного родителя, если родитель
  гарантирует права на всю ветку (проследить по коду).
- Introspection включена только в dev-конфиге.
