# OS command injection

## Суть
Приложение запускает программу операционной системы и передаёт в командную строку
недоверенные данные так, что оболочка интерпретирует их как дополнительные команды
или опции. Результат — выполнение произвольных команд с правами процесса веб-сервера
или воркера: чтение секретов из env и файлов, переход по внутренней сети, полный захват
машины.

## Где появляется в коде

**Python** — главное зло: строка + оболочка.
```python
# плохо
os.system(f"ffmpeg -i {path} out.wav")
subprocess.run(f"ffmpeg -i {path} out.wav", shell=True)
subprocess.Popen("convert " + name, shell=True)
asyncio.create_subprocess_shell(f"sox {src} {dst}")
os.popen(cmd); commands.getoutput(cmd)
# хорошо: список аргументов, без оболочки, с разделителем опций
await asyncio.create_subprocess_exec(
    "ffmpeg", "-nostdin", "-i", str(path), "-f", "wav", str(out),
    stdout=PIPE, stderr=PIPE)
subprocess.run(["git", "log", "--", user_ref], check=True, timeout=30)
```
Даже без `shell=True` остаётся **инъекция аргументов**: значение, начинающееся с `-`,
становится опцией программы (у `git`, `tar`, `curl`, `ffmpeg`, `find`, `rsync`, `ssh`
есть опции, запускающие команды, читающие или пишущие файлы, ходящие в сеть).
Защита — `--` перед позиционными аргументами, где программа это поддерживает,
проверка, что значение не начинается с `-`, или передача пути как `./имя`.

Ещё места: `shlex.split(user_string)` с последующим `exec` (пользователь сам выбирает
аргументы), `subprocess.run(["sh", "-c", ...])`/`["bash", "-c", ...]` — это снова
оболочка, `paramiko.exec_command` на удалённом хосте, `os.exec*` с `PATH`-поиском при
управляемом `PATH`, `ffmpeg`-фильтры и `ImageMagick`-строки, собранные из ввода
(у этих программ свои мини-языки), cron/`at`/systemd-юниты, генерируемые из ввода.

**Node/JS**: `child_process.exec`, `execSync`, `spawn(..., {shell: true})`,
шаблонные строки в командах. Хорошо — `execFile`/`spawn` с массивом аргументов.
**Прочее**: PHP `system`, `exec`, `shell_exec`, обратные кавычки; Java
`Runtime.exec(String)`; Ruby `system("...#{x}")`, `%x{}`, `Kernel#open("|...")`.

## Как искать
```bash
rg -n "shell\s*=\s*True|os\.system\(|os\.popen\(|create_subprocess_shell|getoutput\(|getstatusoutput\(" --type py
rg -n "subprocess\.\w+\(\s*f['\"]|subprocess\.\w+\(\s*\w+\s*\+" --type py
rg -n "\[\s*['\"](sh|bash|cmd|powershell)['\"]\s*,\s*['\"](-c|/c)" 
rg -n "child_process|execSync\(|exec\(\s*`|shell:\s*true" -g '*.{js,ts}'
```
Вопросы ревьюера:
- Нужен ли вообще внешний процесс? Нет ли библиотеки/API на языке приложения?
- Вызов идёт через оболочку? Если да — зачем (пайпы, глоб, переменные)?
- Какие аргументы приходят извне: имя файла, URL, формат, хост, ветка, опции?
- Может ли значение начинаться с `-` или содержать `=`, пробел, перевод строки?
- Какие права у процесса, есть ли таймаут, что он видит в env (ключи API!)?

Источники недоверенных данных: имена загруженных файлов, параметры формата/качества,
URL для скачивания, имена веток/хостов, данные из БД, вывод LLM, сообщения чатов.

## Обходы, о которых забывают
- **Чёрный список метасимволов** почти всегда неполон: разделители команд различаются
  между Unix и Windows, есть перевод строки, подстановка команды, перенаправления,
  глобы, переменные окружения, а у `cmd.exe` — свои правила экранирования.
- **Кавычки вокруг значения** не спасают: атакующий закрывает кавычку сам, а внутри
  двойных кавычек оболочка всё равно выполняет подстановку команд.
- **«Нет вывода — нет уязвимости»** неверно: слепую инъекцию подтверждают задержкой
  времени, записью результата в файл, доступный по вебу, или внешним сетевым
  обращением (например, DNS-запрос, в имени которого спрятаны данные).
- **`shell=False` ≠ безопасно** — остаётся инъекция опций и мини-языки самих программ
  (фильтры ffmpeg, шаблоны ImageMagick, `-o`-опции ssh/rsync).
- **Экранирование одним `shlex.quote`** корректно для POSIX-sh, но не для Windows и
  не для вложенных уровней (команда внутри `ssh host "..."` интерпретируется дважды).
- **Нормализация после проверки**: значение проверили, потом декодировали
  (URL/Unicode) — и запрещённые символы появились уже после фильтра.

## Как исправить правильно
1. Убрать внешний процесс: использовать библиотеку (Pillow, `pydub`/PyAV, `zipfile`,
   `shutil`, HTTP-клиент вместо `curl`).
2. Если процесс нужен — `subprocess.run([...], shell=False, timeout=..., check=True)`
   или `asyncio.create_subprocess_exec`; полный путь к бинарнику; `--` перед
   пользовательскими позиционными аргументами.
3. Строгая валидация по белому списку: формат — из `Literal["wav","mp3"]`, числа —
   как `int` в диапазоне, имена файлов — генерирует сервер (UUID), а не пользователь.
4. Защита в глубину: отдельный пользователь без лишних прав, урезанный `env=`
   (без ключей API), рабочий каталог-песочница, контейнер/seccomp, лимиты ресурсов.
5. Не логировать полные командные строки, если в них есть ПД или секреты.

## Ложные срабатывания
- `shell=True` с полностью константной строкой без внешних значений.
- `create_subprocess_exec`/`subprocess.run([...])`, где все элементы — константы или
  сгенерированные сервером пути (UUID-имена во временном каталоге).
- `shlex.quote` для POSIX-оболочки при одном уровне интерпретации — корректно, хоть и
  хуже, чем отказ от оболочки.
- `exec` в смысле SQL/ORM (`conn.execute`) — это не запуск процесса.
