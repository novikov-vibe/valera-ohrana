# Server-side template injection (SSTI)

## Суть
Недоверенная строка становится частью **шаблона**, а не данными для него, и шаблонизатор
исполняет её как выражение. Современные движки (Jinja2, Mako, Twig, Freemarker, Velocity,
ERB, Handlebars, Pug) дают доступ к объектам языка, поэтому SSTI обычно ведёт к
выполнению кода на сервере, чтению конфигурации и секретов. Отличается от XSS тем, что
исполняется на сервере, а не в браузере.

## Где появляется в коде

**Python / Jinja2**:
```python
# плохо: пользовательский текст склеен в исходник шаблона
Template(f"Здравствуйте, {name}!").render()
env.from_string("Итоги: " + summary_header).render(call=call)
render_template_string(request.args["tpl"])           # Flask
# хорошо: шаблон — константа или файл, ввод — переменная контекста
env.get_template("greeting.html").render(name=name)
Template("Здравствуйте, {{ name }}!").render(name=name)
```
Другие места:
- шаблоны писем/сообщений/выжимок, которые админ или пользователь редактирует в
  интерфейсе и которые потом рендерятся тем же полноценным Jinja2 (`config.yaml`,
  БД-оверрайды промптов и шаблонов — это тоже «шаблон от человека»);
- двойной рендер: результат первого `render()` снова отдаётся в `from_string`;
- Mako `Template(text)`, `string.Template` (безопасен — нет выражений) против
  `str.format(**ctx)` с пользовательской форматной строкой (утечка атрибутов через
  `{obj.__class__...}` — «format string injection», родственная проблема);
- шаблон промпта LLM, собранный Jinja2 из текста пользователя.

**Node/JS**: `ejs.render(userString)`, `pug.compile(userString)`,
`Handlebars.compile(userString)`, `nunjucks.renderString(userString)`,
`lodash.template(userString)`, `new Function`/`vm` для «простых шаблонов».
**Прочее**: Java Freemarker/Velocity/Thymeleaf (выражения в именах представлений,
`__${...}__`-препроцессинг), PHP Twig/Smarty `createTemplate($input)`, Ruby ERB.

## Как искать
```bash
rg -n "from_string\(|render_template_string\(|Template\(\s*(f['\"]|\w+\s*\+|\w+\))" --type py
rg -n "\.format\(\s*\*\*|\.format_map\(" --type py          # пользовательская форматная строка?
rg -n "mako\.template|jinja2\.Template|Environment\(" --type py
rg -n "(ejs|pug|Handlebars|nunjucks|_)\.(render|compile|renderString|template)\(" -g '*.{js,ts}'
```
Вопросы ревьюера:
- Исходник шаблона — константа/файл из репозитория или строка, на которую влияет
  пользователь (включая админа, БД-оверрайд, импорт из внешней системы)?
- Если шаблоны редактируют люди — какая среда используется: `SandboxedEnvironment`?
  Логика-less формат? Какие объекты попадают в контекст?
- Есть ли двойной рендер или рендер результата модели?
- Включён ли `autoescape` (это про XSS, но говорит о культуре шаблонов)?

## Обходы, о которых забывают
- **«Шаблоны правит только админ»** — роль может быть захвачена, а админ ≠ владелец
  сервера; редактирование шаблона не должно давать выполнение кода на машине.
- **Песочница не абсолютна**: из любого объекта в контексте можно добраться через
  атрибуты и наследование к классам интерпретатора. Чем богаче контекст (ORM-модели,
  `request`, `config`, функции), тем больше путей наружу. Песочницы Jinja2 и других
  движков исторически имели обходы.
- **Чёрный список символов/слов** (`__`, `class`, точки) обходится альтернативными
  способами доступа к атрибутам, фильтрами движка и конкатенацией строк внутри
  выражения.
- **Контекст кода, а не текста**: ввод попадает внутрь уже существующего выражения
  (например, имя переменной или фильтра выбирает пользователь) — тогда даже без
  фигурных скобок он меняет логику.
- **Слепая SSTI**: результат не виден, но выполнение подтверждается задержкой или
  внешним запросом. Отсутствие «49» в ответе не доказывает безопасность.
- **Разные движки — разный синтаксис**: проверять одну форму скобок недостаточно,
  атакующий сначала определяет движок по ошибкам.

## Как исправить правильно
1. Никогда не превращать ввод в исходник шаблона: шаблоны — фиксированные файлы,
   пользовательские значения — только через контекст `render(**ctx)`.
2. Если пользователям нужны свои шаблоны — logic-less формат (подстановка
   `{name}` своим кодом по белому списку ключей, `string.Template.safe_substitute`,
   Mustache без лямбд), а не полноценный Jinja2.
3. Если без Jinja2 никак — `jinja2.sandbox.ImmutableSandboxedEnvironment`, минимальный
   контекст из примитивов (str/int/списки словарей), без объектов ORM и функций,
   лимиты длины и времени рендера.
4. Защита в глубину: рендер ненадёжных шаблонов в отдельном процессе/контейнере без
   секретов и сети; `autoescape=True` для HTML.

## Ложные срабатывания
- `Template("...{{ x }}...")` с константным литералом и данными через `render(x=...)`.
- `get_template("file.html")` с именем из кода (если имя файла из ввода — это уже
  path traversal, см. `path-traversal.md`).
- `string.Template(...).substitute()` — выражений нет, только подстановка имён.
- `"{} {}".format(a, b)`, где форматная строка — константа.
- Шаблон задаётся в `config.yaml`, который меняется только через репозиторий/деплой
  (но если есть оверрайд из админки — смотреть внимательно).
